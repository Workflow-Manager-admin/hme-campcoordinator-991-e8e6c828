## Database Table: arrivals

A new table is required for logging member arrivals/departures and status:

- **Table name:** `arrivals`
- **Columns:**
  - `id`: bigint, primary key, auto-increment
  - `user_id`: uuid, foreign key referencing `auth.users.id`
  - `arrival`: timestamp, nullable, user's arrival (date/time)
  - `departure`: timestamp, nullable, user's departure (date/time)
- **Constraints/Indexes:**
  - Unique index on `user_id` (one row per user)
- **Purpose:** Stores each member's expected arrival/departure for dash and crew status.
- **RLS:** Enable row-level security with policies:
  - Each user may insert/update/delete their own row.
  - Readers (any authenticated) may select all for attendance display.

> To create (example SQL):
> ```sql
> create table if not exists arrivals (
>   id bigint primary key generated by default as identity,
>   user_id uuid references auth.users(id),
>   arrival timestamptz,
>   departure timestamptz,
>   unique(user_id)
> );
> -- Add RLS and policies as needed
> ```

#### **Manual Steps for Admin**

1. **Enable the public.run_sql function for API-driven table changes.**  
   In Supabase SQL Editor, run:
   ```sql
   create or replace function public.run_sql(query text)
   returns void as $$
   begin
     execute query;
   end;
   $$ language plpgsql security definer;
   ```
   And grant appropriate access so your API agent can use it.
